# AI Development Log

This document details the AI tools used during the development of the Sodio Enquiry Triage Console, including concrete moments where the model or project environment produced errors and how they were resolved.

## Tools Used
- **Antigravity (Gemini 3.5 Flash - High):** Used as the primary agentic pair programmer. Directed file creation, database schema design, queue implementation, API routes, and styling.
- **Prisma CLI & Schema Validator:** Used to validate database mapping and synchronize migrations.

## Concrete Moments of Correction

Here are three moments during the development process where errors occurred, and how we resolved them:

### 1. The Prisma 7 Datasource URL Deprecation
- **What went wrong:** When attempting to run the initial Prisma migration (`prisma migrate dev`), the CLI failed with error code `P1012`:
  ```
  error: The datasource property `url` is no longer supported in schema files. Move connection URLs for Migrate to `prisma.config.ts`...
  ```
- **What we noticed:** The boilerplate generated by `create-next-app` installed Prisma v7. In Prisma 7, connection URLs have been completely removed from schema files, requiring either `prisma.config.ts` for migration or passing dynamic **Driver Adapters** (e.g. `@prisma/adapter-better-sqlite3`) to the constructor.
- **What we did about it:** Installing driver adapters for SQLite requires building native C++ binaries (`better-sqlite3` via node-gyp) at install-time. If the IT company founder evaluating this code runs `npm install` on a machine without compiler tools (gcc, make, python), the build will fail immediately. 
  To make the project 100% portable and ensure it "just runs" with nothing else configured, we **downgraded Prisma to v5.22.0**. We restored the standard `url = env("DATABASE_URL")` mapping in `schema.prisma` and instantiated a standard `new PrismaClient()` with zero external adapter dependencies, eliminating any compilation risks.

### 2. Missing Company Column in Schema and Type Interface
- **What went wrong:** During our first production build run (`npm run build`), the TypeScript compiler threw a series of errors:
  ```
  app/components/EnquiryDetailDrawer.tsx(77,41): error TS2339: Property 'company' does not exist on type 'DetailedEnquiry'.
  ```
- **What we noticed:** While the prompt requested extracting the `company`, our initial schema and TS interface omitted a dedicated `company` field, storing it only inside the JSON metadata block. The frontend form attempted to bind to a direct `data.company` property which was missing.
- **What we did about it:** 
  1. We modified `prisma/schema.prisma` to add `company String @default("Unknown")` to the `Enquiry` model.
  2. We re-ran the local migration `npx prisma migrate dev --name add_company` to regenerate the Prisma client types.
  3. We updated the `DetailedEnquiry` interface inside `EnquiryDetailDrawer.tsx` to include `company: string`.
  4. We updated `lib/queue.ts` to map the extracted company value directly into the database during batch processing.

### 3. Invalid Comment Syntax in `globals.css`
- **What went wrong:** The Turbopack CSS compiler failed during build:
  ```
  Error: Parsing CSS source code failed
  Unexpected token Semicolon in app/globals.css
  ```
- **What we noticed:** Inside the global stylesheet, we had added single-line Javascript-style comments (e.g. `// Status Colors` and `// Priority Colors`). Turbopack's PostCSS parser strictly adheres to CSS standards, which do not support `//` comments.
- **What we did about it:** We updated `app/globals.css` to replace all single-line comments with standard CSS block comments (`/* Status Colors */`).
